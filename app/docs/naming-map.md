# clpr SQLite → PostgreSQL naming map (D-052 consolidation)

The operator-approved rename map for the consolidation of the three divergent
SQLite DBs into the single PostgreSQL 18 database `clpr`. This is the P2/P3
contract: the consolidation script (P2) and the app port (P3) use these names
and nothing else.

## Table map

| SQLite | PostgreSQL | Notes |
|---|---|---|
| `vods` | `recordings` | plus ONE new column: `display_name TEXT` (nullable) |
| `transcript_segments` | `transcript_segments` | unchanged |
| `beats` | `trigger_beats` | |
| `audio_energy` | `audio_energy_buckets` | |
| `chat_messages` | `chat_messages` | unchanged |
| `chat_raw` | `chat_raw` | unchanged |
| `transcript_signal_candidates` | `llm_signal_candidates` | |
| `candidates` | `clip_candidates` | |
| `clips` | `clips` | unchanged |
| `poison_regions` | `poison_regions` | unchanged |
| `schema_migrations` | `schema_migrations` | unchanged (PG apply-once ledger, D-027 discipline) |

**Excluded: `candidates_v2`** — empty vestige of the failed 005 re-run
diagnosed in D-027 (permanently inert now that the ledger prevents 005 from
re-running); the P2 consolidation script skips it DELIBERATELY, but must still
VERIFY it has 0 rows at merge time and refuse to proceed if it somehow doesn't.

## Column map

- Every `vod_id` FK column becomes `recording_id` (in `poison_regions`,
  `trigger_beats`, `transcript_segments`, `audio_energy_buckets`,
  `llm_signal_candidates`, `chat_messages`, `clip_candidates`).
- `clips.candidate_id` references `clip_candidates(id)`.
- All other columns keep their names.
- New column: `recordings.display_name TEXT` (nullable) — the only column that
  exists in PG and not in SQLite.

## Index map

| SQLite | PostgreSQL |
|---|---|
| `idx_tsc_unique` (uses `IFNULL(trigger_offset_s, -1)`) | `idx_llm_signal_candidates_unique` (uses `COALESCE(trigger_offset_s, -1)` — approved dialect translation) |
| inline `UNIQUE` constraints | ported as table `UNIQUE` constraints under the renamed tables |

## Identity / sequence note for the consolidation (P2)

PG primary keys are `BIGINT GENERATED BY DEFAULT AS IDENTITY` — **BY DEFAULT,
not ALWAYS** — precisely so the consolidation script can INSERT explicit ids
carried over from SQLite. After all rows are loaded, P2 must fix every
sequence, e.g.
`SELECT setval(pg_get_serial_sequence('<table>', 'id'), (SELECT COALESCE(MAX(id), 1) FROM <table>));`
per table, so subsequent app inserts do not collide.

## Type notes (port fidelity)

- SQLite `REAL` → `double precision`; `TEXT` → `text`.
- ISO-8601 timestamps remain `text` — the recency merge compares ISO strings;
  no type conversion.
- CHECK constraints ported verbatim, including `clip_candidates.state`'s
  five-value vocabulary WITH `maybe`, and `recordings.state`'s four values.

## Cutover

At cutover the SQLite files freeze as read-only archives; PostgreSQL `clpr` is
the sole live database from that point on.
